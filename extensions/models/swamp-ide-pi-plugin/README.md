# @svendowideit/swamp-ide-pi-plugin

Install, enable and disable the pi addin that routes tool calls through
`@svendowideit/swamp-ide`, and records every routed and bypassed call.

## What it does

The pi addin is a file in pi's extension directory. This extension owns that
file:

- `install` writes the bundled addin into `<project>/.pi/extensions/swamp-ide.ts`
  or `~/.pi/agent/extensions/swamp-ide.ts`.
- It also writes a global **guard** to
  `~/.pi/agent/extensions/swamp-ide-guard.ts`. When an enabled session has no
  `swamp_ide` tool, the guard restores the baseline tools, records
  `enforced:false` with a reason, and the panel shows "tracking off". A missing
  tracker degrades visibly; it never blanks the tool set and locks the person
  out.
- When a Herdr approval dialog is available it shows the reason, goal, exact
  command/path, risk and effect. Approve writes the lease, Deny and Explain
  return to the agent, and closing the dialog (X or Esc) resolves the request as
  a fallback so the agent returns the explicit `/swamp-ide approve <scope>
  <duration>` command immediately. The dialog's Copy button writes the full
  request to `last-request.txt` and the clipboard. For an exact `file:<path>`
  or `protected:<path>` request it also shows the parent directory and a
  **Grant directory** button: that writes a `dir:<absolute directory>` lease
  covering every file below the directory, so the same directory does not need
  one approval per file. Protected directories are available and carry HIGH
  risk; the button is not offered for the filesystem root.
- It refuses to overwrite or remove a file that does not contain its managed
  marker, unless `force=true`.
- `set enabled=true` writes the session marker used by the addin; `enabled=false`
  removes that session's marker, or all markers when no session id is given.
- `uninstall` removes the managed file and every marker for the scope.
- `status` reports pi availability, the install path, and which sessions are
  enabled.

The addin itself exposes `swamp_ide`, prefers it over built-in file/shell tools,
and records routed and bypassed tool calls as OTLP spans and JSONL activity
events for the Herdr panel. In `enforce` mode the addin and guard make
`swamp_ide` the only active tool **while it is registered**; if it is missing
they leave the baseline tools enabled and report tracking as off. It runs
methods through a single warm `swamp serve` WebSocket per session
and falls back to the CLI only when that connection cannot be established. It
also keeps a per-program histogram of the bash commands that still bypass the
IDE, so the next herdr-core/vim method can be chosen from real use. `system=swamp`
lets `swamp_ide` run any swamp model method, including the OpenObserve dashboard.
`@svendowideit/swamp-ide` calls `set` so one command can enable or disable the
whole system.

Every `swamp_ide` result begins with a deterministic `Authorization:` line
generated by the addin. It states whether the call was read-only, covered by an
existing lease, approved through the Herdr dialog, or blocked/denied/timed out,
and why. The same structured fields are stored in the activity event and OTLP
span, so the panel and traces agree with the line the assistant quotes.

## Install

```sh
swamp extension pull @svendowideit/swamp-ide-pi-plugin
```

pi must be on PATH, or a `~/.pi/agent` install must exist. The addin imports
`typebox` from pi itself; no extra dependency is installed.

## One instance per pi session

Swamp's lock is per model instance, so every session sharing `herdr-core` (or
`vim-controller`) queues behind whichever call is in flight — including
read-only ones, which take the same lock. Each pi session therefore gets its own
instances, created against the running serve the first time it needs one:

```
herdr-core-pi-<terminal>-<session>      e.g. herdr-core-pi-t2g-01a20665
vim-controller-pi-<terminal>-<session>  e.g. vim-controller-pi-t2g-01a20665
```

`<terminal>` is the pane's `HC_TERMINAL_ID` (which `herdr-app ls` maps to a space
and tab) and `<session>` is the first eight characters of the pi session id — so
the name answers "which window, which conversation". The instance is recorded in
every activity event, which means the panel, `swamp run doctor` and
`swamp model list` all name the same thing when something is stuck.

If the instance cannot be created (a serve that refuses `model create`, a
read-only repo), the call falls back to the shared instance and the event records
that instead. The instances live under `models/@svendowideit/<behaviour>/`, one
file per session and behaviour, and are safe to delete when the session ends
(`swamp model delete <name>`).

## One editor, one write path

Text file mutations are not written behind the editor's back. A
`system=herdr-core` call to `file-write`, `file-edit` or `file-edit-lines` is
mapped to a single `editFile` call on `@svendowideit/vim-controller`, which makes
sure this space's `Edit` tab is running, loads the path into its buffer, applies
the edits (line ranges bottom-up, with `expectedLines`/`expectedHash`
preconditions) and saves. The person watching the editor sees exactly the change
the file received, and the activity event records `via: "vim"` with the path as
its target.

Three cases deliberately stay on herdr-core, each recorded with its reason in the
event (`via: "herdr-core"`): a call naming a remote `machine`, content containing
a NUL byte, and a binary file extension. If the editor cannot be reached at all,
the write falls back to herdr-core with `reason: "editor unavailable"` rather than
failing the turn. `file-read` and `search` keep reading the disk: after a save the
buffer and the file hold the same bytes, and a search has to span files no buffer
has opened.

## Permission policy

The addin is not allowed to change the live setup by itself. A human-only lease
is required for every mutating call. The human runs this in pi:

```text
/swamp-ide approve <scope> [minutes]
/swamp-ide revoke
/swamp-ide lease
/swamp-ide log [n]
```

`/swamp-ide log` prints one line per recent activity event — time, `via`, what
was called, outcome and duration — plus a summary count of `ws` against `cli`,
so the question "which calls still need a shell" is answerable from a terminal.
`via` is `ws` for the serve socket, `cli` for a spawned `swamp` process (with the
reason it fell back), `herdr-core`/`vim`/`guard`/`bypass` for those routes, and
`none` for an event written before the field existed.

Scopes are exact strings, for example:

- `swamp:ide-pi.set` — the pi addin installer/session gate
- `swamp:ide.setHerdr` — the Herdr panel/layout
- `swamp:ide-openobserve.dashboard` — the dashboard
- `exec`, `run`, `send`, `keys`, `interrupt`, `kill`, `rm`, `put` — herdr-core
- `vim:edit`, `vim:write`, `vim:command` — Vim mutations
- `file:<absolute path>` — one non-protected file
- `dir:<absolute directory>` — every file below that directory (not `/`), for
  example from the dialog's **Grant directory** button
- `protected:<absolute path>` — one protected path
- `protected` — any protected path (a broad grant that the dialog rejects)
- `all` — any scope (a broad grant that the dialog rejects)

Protected paths include the addin, guard, policy, `~/.pi` extension/marker
directories, Herdr mods/layouts, the swamp-ide state directory and the
swamp-ide extension sources. Read-only calls (`status`, `file-read`, `search`,
`read`, `terminals`, `machines`, `vim:read`, etc.) do not need a lease. Missing,
expired, wrong-session or wrong-scope leases fail closed.

## Configuration

| Global argument | Default | Meaning |
| --- | --- | --- |
| `piBin` | `pi` | pi executable |
| `scope` | `project` | Install into the project `.pi` or `~/.pi/agent` |
| `projectDir` | `""` | Project root for project scope; empty uses the current directory |
| `force` | `false` | Overwrite/remove a destination that is not managed |

`set` takes `enabled` and optional `sessionId` (empty discovers the newest
live pi session; explicit values target a specific session). `install` and
`uninstall` take optional `scope` and `force` overrides.

| Addin environment variable | Default | Meaning |
| --- | --- | --- |
| `SWAMP_IDE_MODE` | `enforce` | `off`, `advise`, or `enforce` |
| `SWAMP_IDE_SERVE` | unset | `off` disables the serve fast path |
| `SWAMP_SERVE_URL` | `ws://127.0.0.1:9090` | swamp serve endpoint |
| `SWAMP_AGENT_IDE_EVENT_LOG` | `~/.local/state/swamp-agent-ide/events.jsonl` | activity events for the Herdr panel |
| `SWAMP_AGENT_IDE_SHELLOUT_LOG` | `~/.local/state/swamp-agent-ide/shellouts.jsonl` | shell-out histogram records |
| `SWAMP_IDE_OTEL_ENABLED` | `true` | set `false` to stop span export |

## Examples

Install the managed addin globally, so project trust cannot leave it unloaded:

```sh
swamp model @svendowideit/swamp-ide-pi-plugin method run install ide-pi \
  --input scope=global
```

Enable it for the current pi session, then restart pi:

```sh
swamp model @svendowideit/swamp-ide-pi-plugin method run set ide-pi \
  --input enabled=true --input scope=global \
  --input sessionId="$PI_SESSION_ID"
```

Report what is installed and which sessions are enabled:

```sh
swamp model @svendowideit/swamp-ide-pi-plugin method run status ide-pi
```

Disable it for every session without removing the managed file:

```sh
swamp model @svendowideit/swamp-ide-pi-plugin method run set ide-pi \
  --input enabled=false
```

## Details

Model type: `@svendowideit/swamp-ide-pi-plugin`.

| Method | Data written |
| --- | --- |
| `install` | `plugin` (instance `swamp-ide`) |
| `set` | `plugin` (instance `swamp-ide`) |
| `uninstall` | `plugin` (instance `swamp-ide`) |
| `status` | `plugin` (instance `swamp-ide`) |

Managed paths:

- project addin: `.pi/extensions/swamp-ide.ts`
- global addin: `~/.pi/agent/extensions/swamp-ide.ts`
- policy: `.pi/extensions/swamp-ide-policy.ts` or
  `~/.pi/agent/extensions/swamp-ide-policy.ts`
- approval lock: `.pi/extensions/swamp-ide-lock.ts` or
  `~/.pi/agent/extensions/swamp-ide-lock.ts`
- global guard: `~/.pi/agent/extensions/swamp-ide-guard.ts`
- markers: `.pi/swamp-ide/<session>.enabled` or
  `~/.pi/agent/swamp-ide/<session>.enabled`

The guard is always global: it must load even when a project-local addin does
not. In an enabled session it makes `swamp_ide` the only active tool; if the
addin is missing it disables all tools and writes the reason to the event log
and `addin.json` / `guard.json` heartbeats. The Herdr Swamp IDE panel reads those
heartbeats and shows `all active`, `degraded`, or `tracking off` with the age of
the last heartbeat.

## Upgrade

```sh
swamp extension update
```

Re-run `install` after an upgrade to refresh the managed addin.

## Serve fast path and shell-out histogram

After `/reload`, the addin opens one WebSocket to `SWAMP_SERVE_URL` and sends
`model.method.run` requests over it. The connection is cached for the session; a
failed connect is retried after 30 seconds. If serve is not reachable, the
addin spawns the CLI exactly as before. Once a request has been sent it is never
retried through the CLI, because the method may already have produced data.

Every bash tool call is split into shell segments and its executable is appended
to `SWAMP_AGENT_IDE_SHELLOUT_LOG` as one JSON object per program. In pi:

- `/swamp-ide` shows the serve connection and the top five programs.
- `/swamp-ide histogram` shows the top twenty programs and program+subcommand
  counts, with `bypass`/`other` totals.

The same program and subcommand are attached to the OTLP span as
`swamp.agent.shell.program`, `swamp.agent.shell.subcommand`, and
`swamp.agent.shell.category`, so the dashboard can group them too.
