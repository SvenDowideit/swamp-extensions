What's Changed

  • feat(issue): swamp issue bug, feature and security can file against the platform source with --source platform (swamp-club#4239) (#3526)

Summary

Any logged-in user can now file a bug, feature or security report against the platform source with --source platform. Without the flag, the commands file with the source they use today.

  • --source accepts swamp or platform, and is refused with --extension and --email. The check runs before auth, extension lookup and the editor.
  • A report with a chosen source never falls back to email, which cannot carry a source. When not logged in it gets the login error with no prompt, and a timeout no longer suggests --email.
  • JSON output gains source: "platform" only for platform filings, and log output gains one line.
  • The platform source is separate from the admin-only platform type, which still cannot be filed from the CLI. The issue guide in the swamp skill says so.

Not in this PR

The manual page lives in the swamp-club repo, so it is not updated here.

What's Changed

  • fix(serve): dashboard sign-in accepts HTTP/2 requests, and --groups-field help names only the collectives field (swamp-club#4229, swamp-club#4187) (#3527)

Summary

Fixes two swamp serve issues:

  • swamp-club#4229: dashboard sign-in was refused over HTTP/2. validateDashboardSessionOrigin read only the Host header, but Deno exposes the HTTP/2 authority through Request.url and leaves that header null. Every HTTP/2 request to the dashboard session and device endpoints got 403 missing host, even with a matching origin and --trusted-hosts set. A proxy re-encrypting to serve hits this, because HTTP/2 is Caddy's default for an https:// upstream. It now falls back to the request URL, as the no-auth API check already does.
  • swamp-club#4187: the --groups-field help said it names the field for group/collective memberships. It names only the collectives field, so the help text and design/primitives/serve.md now say that.

The manual changes for #4229 are in a companion swamp-club PR, branch 4229.

Behaviour changes

  • A request with no Host header now uses the authority in the request URL. That includes HTTP/1.0 requests with no Host, which were previously refused. An empty Host header is still refused.
  • The exact origin match is unchanged, and foreign origins are still refused.
